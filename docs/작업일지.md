# 작업일지

## 2026-09-07 — 착수부터 v0.1.1 공개까지 (하루)

### 시작점
빈 디렉터리. 자매 프로젝트(kci·scienceON·nl)의 아키텍처를 따르되 **API 사실은 옮기지
않고 각자 실측한다**는 원칙으로 시작했다.

### API 확정 — 문서가 여러 곳에서 틀렸다
공공데이터포털에서 대상 API 두 개를 찾고(자료검색 `15098174`, 상세정보조회 `15098175`)
공식 `.hwp`/`.docx` 를 받아 읽은 뒤, **파라미터·스키마·상한을 전부 라이브 왕복으로 확인**했다.
문서와 다른 곳이 이만큼 나왔다:

| 항목 | 문서 | 실제 |
|---|---|---|
| 레코드 태그 | `<record>` | **`<recode>`** |
| `<item>` 자식 순서 | value→name | name→value |
| 제어번호 필드명 | `controlno` | `제어번호` |
| `displaylines` 상한 | 100 | **1000** |
| 인증키 | (언급 없음) | Encoding 값을 URL 에 직접 결합 |
| 하이라이트 | (언급 없음) | 매칭 필드에 `<font color="red">` |

`<recode>` 는 특히 위험했다 — 문서대로 만들었으면 **전건 0개를 회수하면서 `total` 은
정상으로 보고**했을 것이다. 이 저장소가 막겠다고 한 실패 양식 그대로다.

### API 고유의 함정
- **미지원 검색항목 = 전체 카탈로그 1,300만 건** (오류 아님). `저자명` 은 상세검색에서는
  유효한 이름이라 헷갈려서 쓰기 쉽다 → 화이트리스트로 호출 전에 거부.
- **상세검색은 정반대** — 틀린 검색항목·dbname 을 ERR04 로 거부한다. 그런데 그 코드가
  일시 오류와 같아 재시도를 낭비하므로 역시 호출 전에 막는다.
- **`pageno ≤ 99`** 하드 상한 → 회수 한계 `99 × page_size`.
- **`ERR04` 는 재시도 대상** — 깊은 오프셋에서 간헐 발생하며 단조롭지 않다.
- **`requests.text` 금지** — charset 없는 헤더 탓에 chardet 가 `고서` 응답을 ptcp154 로
  추측해 한글이 통째로 깨졌다. 일반도서가 멀쩡했던 건 우연이었다.

### 자료종 census (표본 약 21,000건)
13종을 500건씩 연도 층화로 떠서 필드 실태를 확정했다. 안내문이 값 자리에 오는 것
(E-BOOK DDC 99.95%), 구조적으로 빈 필드, 목차가 전건 없는 자료종, 이름과 내용이 다른
필드(`국회회의록/발언자` 는 상수 `대한민국 국회`), 서술형 본문은 의안정보·회의록에만 존재.

### 🔴 적대적 리뷰 — 결함 33건
회귀 107건을 통과하고 라이브 왕복도 정상이던 코드에 에이전트 48개로 5개 렌즈 리뷰를
돌리고 지적마다 독립 반증을 붙였다. **확정 33건, 기각 9건. 전부 내가 그날 넣은 것들이다.**

- **데이터 손상** — `clean_html` 이 임의의 `<…>` 를 지워 표제를 망가뜨렸다
  (`<표 124> …`, 표,그림DB 는 거의 전부 이 형태). 라이브 1,000건 중 18건 손상.
- **검증 우회 3종** — 검증기가 strip 한 문자열을 버리고 원문 전송, `search='|'` 통과,
  `extra_params` 가 검증 끝난 값을 덮어쓰고 meta 는 덮어쓰기 전 값을 보고.
- **조용한 절단 4종** — 회수 한계를 상수로 판정, 조기 종료 무신호, `option` 무시 무경고,
  수집 경로가 경고를 통째로 버림.
- **누출 2종** — urllib3 DEBUG 가 인증키 든 URL 을 찍음, `_envelope` 이 태그 이름만 검사.
- **소표본 단정** — 고서 `ISBN` '전건 빈값'이 795건 재측정에서 10건으로 반증.
- **census 층화 붕괴** — 범위 옵션이 최신순이라 표본이 상한 연도 한 해로 수렴했다.
  '3개 구간'이 실제로는 '3개 연도'였다.

전부 수정하고 회귀 107 → 170.

### 공개
GitHub 공개 → CI 이식 → 릴리스 파이프라인 이식 → v0.1.0 → v0.1.1.

- **CI 가 첫 실행에서 환경 의존 테스트를 잡았다** — 쿼터 가드 테스트가 인증키 존재를
  전제해 로컬에서만 통과했다.
- **v0.1.0 이 마지막 단계에서 422 로 거부됐다** — 레지스트리 `description` 100자 제한을
  107자로 넘겼다. 바이너리 3종을 다 빌드하고 Release 까지 만든 뒤였다. 제약을 pytest 로
  고정하고 릴리스 단계를 멱등하게 바꾼 뒤 v0.1.1 로 발행했다.
- v0.1.0 릴리스는 지우지 않고 뒀다 — 자산은 정상이고 레지스트리에만 없다.

### 이날의 교훈
같은 문장이 세 번 다른 층에서 반복됐다.

1. **문서 통과가 정확성의 근거가 못 된다** — 공식 규격서가 6곳에서 틀렸다.
2. **테스트 통과가 정확성의 근거가 못 된다** — 107건 통과 코드에서 33건이 나왔다.
3. **로컬 통과가 이식성의 근거가 못 된다** — CI 가 첫 실행에서 잡았다.

그리고 반복해서 물린 자기 모순 — **내가 문서에 적어둔 원칙을 내 코드가 안 지킨** 사례가
하루에 세 번이었다(ERR04 재시도를 적고도 탐침에 안 넣음, 소표본 금지를 적고도 30건으로
단정, 조용한 절단 금지를 적고도 세 갈래로 냄).
