### 1-1. 🔑 인증키는 **Encoding(퍼센트인코딩) 키를 URL 에 직접 붙여야** 한다
✅ **실측 대조**(같은 요청, 키 표현만 변경):

| 방식 | 결과 |
|---|---|
| Decoding 키를 `requests` 의 `params=` 로 전달 | ❌ `ERR04 HTTP_ERROR` |
| **Encoding 키를 URL 문자열에 직접 결합** | ✅ `resultCode=00` 정상 |
| 키 없음(대조군) | `HTTP 401` + `SERVICE_KEY_IS_NULL` / 코드 20 |

문서에도 `인증키(URL Encode)` 로 적혀 있다. `params=` 로 넘기면 `%2B` 가 `%25 2B` 로
**이중 인코딩**되어 서버가 다른 키를 받는다. 증상이 그냥 '인증 오류'라 원인 추적이 어렵다.
→ 코드에서는 **반드시 URL 직접 결합**. `config.build_url()` 이 이 한 곳을 담당한다.

### 2-3. `GET /detail` — 상세검색 목록조회

`/basic` 파라미터 + 아래.

| 파라미터 | 필수 | 크기 | 설명 | 등급 |
|---|---|---|---|---|
| `dbname` | ✔ | 20 | 검색대상 DB (아래 21종 중 정확한 문자열) | 📄 |
| `option` | ✖ | 500 | `발행년도,2000\|발행년도,2010` — 하나면 그 해부터 현재까지, 둘이면 between. `원문유무,1`(유)/`0`(무) | 📄 |

> ✅ **`option` 은 선택이 맞다** — 실측으로 확인했다(`option` 없이 `/detail` 호출 정상,
> `option="발행년도,2020|발행년도,2024"` 를 걸면 166건 → 8건으로 **서버측에서** 좁혀졌다).

**① 문서에 있으나 거부되는 이름 (전부 ERR04)**
`발행년도` `학위년도` `본문언어` `발행언어` `저작권허락` `초록유무` `원문DB유무`

`대수` `위원회` `회의` `회수` `기간` `내용형식` `내용연도` `국가` `법률주제` `상임위원회`

**③ 슬래시가 든 이름은 한 덩어리다**
`수록지명/신문명`(학술지·잡지·신문) · `CIS/UNSA`. `수록지명` 만 쓰면 학술지·신문에서 ERR04다

**④ `지식공유` 는 어떤 항목도 통하지 않는다**(전체항목 포함) — dbname 자체가 무효로 보인다.

### 2-7. 🔴 인코딩 — `requests.text` 를 쓰면 조용히 깨진다 ✅ 실측

응답은 정상 UTF-8 이고 XML 선언도 `encoding="UTF-8"` 이다. 그러나
**`Content-Type: application/xml` 에 charset 파라미터가 없다.**
→ `requests` 는 `resp.encoding=None` 이 되어 **chardet 추측**에 의존하고,
   `dbname=고서` 응답에서 **`ptcp154`(카자흐 키릴)로 추측**해 한글이 통째로 깨졌다
   (`제어번호` → `м ңм–ҙлІҲнҳё`).
⚠️ `일반도서` 가 멀쩡했던 것은 우연히 utf-8 로 추측됐기 때문이지 옳아서가 아니다.
   **자료종에 따라 무작위로 깨지는 조용한 데이터 손상**이다.
→ 클라이언트는 `resp.content`(bytes)를 그대로 넘기고 **ElementTree 가 XML 선언을 존중**하게 한다.
  회귀 테스트로 `resp.text` 사용을 금지했다.

### 2-4. `GET /detailinfoservice/detail` · `/toc` — 상세정보·목차 ✅ **라이브 검증 완료**

별도 데이터셋(data.go.kr `15098175`, 개발단계 자동승인)이지만 **인증키는 계정 단위라
자료검색과 같은 키가 그대로 통한다**(활용신청만 별도).

파라미터: `serviceKey`, **`controlno`** (검색 결과의 `제어번호`). 페이징 없음.

**🔴 검색 서비스와 봉투 모양이 다르다** — 공용 파서로 묶을 수 없다:

| | 검색(`searchservice`) | 상세정보(`detailinfoservice`) |
|---|---|---|
| 레코드 | `<recode>` 안에 `<item>` | **`<item>` 이 최상위에 평탄하게** |
| 목차 | 없음 | `<toc>` 가 **`<header>` 앞**에 온다 |

```xml
<!-- /detail -->
<response><header>…</header>
  <item><name>제어번호</name><value>KDMT1…</value></item>
  <item><name>논문명</name><value>…</value></item>…
</response>
<!-- /toc — ⚠️ toc 가 header 보다 앞 -->
<response><toc>&lt;p&gt;추천의 글&lt;BR&gt;…</toc><header>…</header></response>
```

#### 🔴 정정: 상세조회는 검색보다 더 주지 않는다 ✅ 실측
검색 결과의 원본 필드(`Record.raw`)와 `/detailinfoservice/detail` 의 필드가 **집합도 값도 완전히
동일**하다. 자료종 5종(일반도서 19 · 학위논문 18 · 국내기사 13 · 고서 19 · 웹자료 17)에서
**상세전용 필드 0개, 값이 다른 필드 0개**.
→ 이미 검색한 자료에 상세조회를 덧붙이는 것은 **쿼터 낭비**다. 제어번호만 아는 자료를 조회할
   때만 쓴다. 반면 **`/toc` 는 검색에 없는 목차 본문을 준다** — 그쪽은 값어치가 있다.
⚠️ 초판 문서에 "검색보다 필드가 많다"고 적었던 것은 **정규화 컬럼(24개 고정)과 상세 raw 를
   비교한 착각**이었다.

자료종별 필드 수 ✅ 실측:
- 도서 **19개** — 제어번호·자료명·저자명·발행자·키워드·목차·ISBN·ISSN·DDC·CIS/UNSA·
  청구기호·본문언어·저작권허락·초록유무·발행년도·별치기호·**원문DB유무**·음성지원유무·자료실
- 학위논문 **18개** — 위와 유사하되 **논문명·지도교수·전공·학위구분·학위년도**
- 국내기사 **13개** — 기사명·수록지명 중심

### 2-8. 🔴 저자·역자·제목·원제가 **분리되지 않는다** ✅ 실측

**저자명 — 필드 1개, 레코드당 값 1개, 역할은 문자열에 섞여 있다**

| 실제 값 | 역할 표기 방식 |
|---|---|
| `지은이: 이선희` | 접두 |
| `루이 알튀세르 지음` | 접미 |
| `민병훈 옮김` | 접미(역자) |
| `호메로스 원작` · `팡추야 글` · `아리아나 필즈 그림` | 접미(기타 역할) |
| `토미 그린월드 [지음]` | 대괄호 |
| `피에르 부르디외` | **표기 없음** |

🔴 **공저자·역자가 잘린다.** 원문 XML 을 직접 계수한 결과 `<item name="저자명">` 은
   **레코드당 정확히 1개**다(중복 없음). 공식 문서의 예시조차
   `지은이: 이선희,김민주,이원호,이종호,김혁순,강태홍,정진웅,임선희`(8인)인데
   실제 API 는 **`지은이: 이선희` 만** 준다.
   → 번역서의 **원저자와 역자를 동시에 얻을 수 없다.** 어느 쪽이 실리는지는 레코드마다 다르다
     (`재생산에 대하여` → 원저자만, `다케토리 모노가타리` → 역자만).

**자료명 — 제목·부제·원제·총서가 한 필드에 뭉쳐 있고 구분자가 일정하지 않다**
- `『자본』을 읽자 / Lire le Capital 프리즘 총서 ;`
- `상속자들 : 학생과 문화 / Les héritiers : les étudiants et la culture` ← **원제 안에도 `:`**
- `텔레비전에 대하여 / Sur la télévision : suivi de L'emprise du journalisme 東文選 文藝新書 ;`
- `기초생명과학 실험서 /` ← 저자사항이 떨어져 나가며 **꼬리 슬래시**만 남음
- 실측 40권 분포: ` / ` 0개 **17권** · 1개 **23권**(그중 9권은 `;` 로 끝남)
→ ` / ` 를 원제 구분자로 가정한 파싱은 **절반에서 어긋난다.** 총서명은 원제 뒤에
  **구분자 없이** 이어붙는다(`Cours sur Rousseau 프리즘총서 ;`).

⚠️ **같은 뜻인데 이름이 다르다**: 도서는 `원문DB유무`, 기사·학위논문은 `원본DB유무`.
⚠️ 검색 **카테고리명**은 `지도교수(2009~)` 인데 상세정보 **필드명**은 `지도교수` 다.
⚠️ 목차 본문은 **HTML 이 이스케이프되어** 온다(`&lt;p&gt;`·`&lt;BR&gt;`). 풀지 않으면
   태그 범벅 한 줄이 된다. 문서의 `toc` 항목크기 `100` 은 의미 없다(실제 수천 자).
⚠️ **목차가 없는 자료도 정상**이다 — 검색·상세의 `목차` 필드가 `Y` 인 것만 부르면
   헛호출과 쿼터 낭비를 줄일 수 있다.

🔴 **존재하지 않는 제어번호도 `ERR04`** 로 응답한다(실측) — 전용 '자료 없음' 코드가 없다.
   그런데 `ERR04` 는 깊은 오프셋의 **일시 오류 코드이기도** 하다. 코드만으로 구분할 수 없으므로
   단건 조회는 재시도를 **2회로 줄이고** 실패 메시지에 '제어번호 확인' 안내를 넣었다.

## 3. 🔴 페이징 한계 — `pageno ≤ 99` (하드) + 깊은 오프셋 간헐 실패

✅ 실측:

**(A) `pageno` 최대 99 — 절대 규칙.** `displaylines` 와 무관하다.
`displaylines=1` 로 크기 영향을 제거한 대조: `pageno` 98 ✅ · 99 ✅ · **100 ❌ · 101 ❌ · 150 ❌**.

→ **한 검색식으로 회수 가능한 최대 = 99 × 1000 = 99,000건.**
(자매 API 국립중앙도서관의 500건 상한과 비교하면 **198배**다. 대부분의 검색식은 분할이 필요 없다.)

**(B) 깊은 오프셋은 간헐적으로 `ERR04` — 경계가 아니라 타임아웃이다.**
`displaylines=1000` 기준: p12 ✅ · p15 ✅ · p20 ✅ · **p30 ❌** · p40 ✅ · p50 ✅ · **p60 ❌**
→ **단조롭지 않다.** 같은 요청 3회 반복에서 p95 는 처음 실패했다가 이후 3/3 성공했다.
🔴 따라서 **`ERR04` 를 종료 조건으로 쓰면 수집이 임의 지점에서 조용히 잘린다.**
→ **재시도(지수 백오프) 대상으로 다룬다.** 반면 `pageno>99` 는 재시도해도 소용없다 —
   이 둘을 **분리**하는 것이 이 클라이언트의 핵심(`cap_hit` vs 일시 오류).

**(C) 페이징 자체는 정상.** p1∩p2 = 0건, p1∩p50 = 0건(중복 없음).
`displaylines=1000` 은 **고유 제어번호 1000건**을 실제로 준다(빈값 0).

### 4-1. 🔴 검색 결과에는 하이라이트 마크업이 섞인다 ✅ 실측

**검색 서비스(`/basic`·`/detail`)는 검색어가 매칭된 필드에 `<font color="red">…</font>` 를 넣는다.**
문서에는 이 이야기가 전혀 없다.

| 호출 | 마크업 |
|---|---|
| `/basic` `전체,양연동` | ✅ 저자명에 삽입 |
| `/detail` 학위논문 `저자명,양연동` | ✅ 저자명에 삽입 |
| `/detail` 일반도서 `자료명,재생산에 대하여` | ✗ 없음 |
| `/detailinfoservice/detail` (제어번호 조회) | ✗ 없음 — **검색이 아니므로** |

⚠️ 초기 탐침이 `전체,교육` 처럼 **제목에 매칭되는 검색어만** 써서 이 현상을 놓쳤다.
   저자명으로 검색해 보고서야 드러났다 — **매칭 필드를 바꿔가며 확인해야 한다**는 교훈.
→ `models.clean_html()` 이 태그를 제거하고, `raw` 에는 **원문을 남긴다**
  (어느 필드가 매칭됐는지가 그 자체로 정보다).

⚠️ **공백은 접지 않는다.** `키워드` 는 여러 칸 공백을 **구분자로** 쓰므로(`주제어A   주제어B`)
   접으면 경계가 사라진다. 자매 프로젝트(국립중앙도서관)는 토큰마다 `<span>` 이 붙어 공백
   정규화가 필요했지만 **여기는 필드 전체를 한 번 감싸므로 태그만 지우면 된다** — 사실을 이식하지 말 것.

> ⚠️ 이 표본은 기사 편중이라 **도서·학위논문의 필드는 다르다**(문서상 `자료명`·`청구기호`·
> `학위`·`학위년도`·`대학` 등). ❓ 자료종별 필드 분포는 추가 실측 필요.
> ⚠️ 문서 예시에 있던 `DB` 항목은 **실응답에 없었다**(0/100).
> → **`raw` 에 name/value 전체를 보존**하고, 정규화는 알려진 이름만 매핑한다.

## 5. 오류 처리 ✅ 실측 + 📄

**성공 봉투와 오류 봉투는 루트 元소가 다르다** — 이것이 1차 판별 기준이다.

| 상황 | 루트 | 내용 |
|---|---|---|
| 정상 | `<response>` | `header/resultCode=00` |
| 게이트웨이 오류 | `<OpenAPI_ServiceResponse>` | `cmmMsgHeader/errMsg`·`returnAuthMsg`·`returnReasonCode` |

✅ 실측한 오류: `04 HTTP_ERROR`(깊은 오프셋·Decoding 키) · `20 SERVICE_KEY_IS_NULL`(키 없음, HTTP 401)

📄 코드표: `01` 앱 · `04` HTTP · `10` 잘못된 파라미터 · `11` 필수 파라미터 없음 · `12` 서비스 없음 ·
`20` 접근거부 · `22` **일일 요청한도 초과** · `30` 미등록 키 · `31` 기한만료 · `32` 미등록 IP · `99` 기타

> ⚠️ **`04` 는 재시도 대상, `22`·`30`·`31` 은 재시도 무의미**(각각 쿼터·키 문제). 분리 처리한다.
> ⚠️ 오류 봉투가 요청을 에코하는지는 ❓ 미확인 — 자매 API(kci)에서 에코로 **인증키가 샜다**.
>    확정 전까지 파서가 봉투에서 자격증명형 키를 제거한다.

## 6. 수집 전략 (자매 프로젝트와 다른 점)

국립중앙도서관(500건 상한)과 달리 **99,000건**까지 받을 수 있어 분할 압박이 훨씬 낮다.

   메타에 노출한다 — 조용히 넘기지 않는다.
4. 검색어 변형은 `|` AND 연산이므로 **OR 합집합은 클라이언트에서** 개별 검색 후 병합한다.

## 8. 자료종별 출력 필드 실태 ✅ 전수 census (2026-09-07)

> 재현: `python scripts/probe_fields.py [dbname …]`
> 방법: 자료종마다 **500건씩 × 연도 3층 × 검색어 2종**.
> 🔴 **정정** — 초판은 층을 `2000-2010`·`1960-1989` 같은 **범위**로 적었으나,
>    `발행년도,A|발행년도,B` 는 [A,B] 안에서 **최신순**으로 주므로 page 1 만 받으면
>    표본이 **상한 연도 한 해**로 수렴한다(적대적 리뷰 실측: `1960|1999` 로 1,000건을
>    받으면 학위년도가 전건 1999). 즉 실제 표본은 '3개 구간'이 아니라 **3개 연도**였다.
>    스크립트는 단일연도 앵커(`최신 / 2010년 / 1989년`)로 바꿔 정직하게 표기한다.
> ⚠️ 따라서 아래 채움률은 **해당 연도 표본의 값**이지 모집단 비율이 아니다.

> 재측정에서 10건이 뒤집혔다. 원인은 **무필터 검색이 깊이 500건까지 최신 연도로 채워지는 것**이라,

### 8-5. 🔴 날짜·연도 함정

- **외국법률번역DB 는 `0` 을 '없음'으로 쓴다.** `관보발행일`·`폐지일` 은 400건 전부 `0`(상수),
  `제정일`·`개정일`·`시행일`·`서명일` 도 상당수가 `0`. 정수 변환하면 1970-01-01 이 된다.
- **발행년도가 4자리가 아닌 경우** — 고서 **23%**(빈값 44건 + `19--` 1건),
  일반도서 1%(`201u` 43건), 학술지·잡지 1%(`201u` 48건), 세미나자료 0.2%.
  `201u` 는 MARC 의 **불확정 연도 표기**다. `models.normalize_pub_year()` 가 빈 문자열을
  돌려주므로 안전하지만, 직접 `int()` 하면 깨진다.
- **연도 층화(`option=발행년도,…`)가 통하지 않는 자료종**: 국회회의록·국회의안정보·
  외국법률번역DB·표,그림DB(ERR04) · 전자저널(무시됨). 각각 `기간`·`제안일자`·`제정일`·
  `내용연도`·`제공년도` 를 쓰기 때문이다.

### 8-7. 기타 실무 메모

- **국외기사는 한국어 검색어로 0건이다**(`전체항목,한국` → total=0). 영문으로만 검색된다
  (`education` 21,749건 · `japan` 5,721건).
- **`외국법률번역DB`·`표,그림DB` 는 `displaylines=500` 에서 ConnectionError 로 끊긴다.**
  레코드가 무거운 자료종이라 200 이하로 낮춰야 한다.
- 상수라 필터로 쓸 수 없는 필드: `원문DB유무`(전 자료종 `Y`), E-BOOK 의 `저작권허락`·
  `별치기호`·`음성지원유무`, 고서의 `자료실`.
